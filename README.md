# winmac

Windows CMD와 macOS zsh의 명령어, VS Code 단축키를 나란히 보여주는 입문자용 사전. 초안 단계에서 개발 중단.

## 상태

중단. 이유는 [중단 사유](#중단-사유) 참고.

## 배경

VS Code로 개발 입문 수업을 듣는데 강사는 Windows, 사용자는 Mac을 쓰는 경우 발생. 강사가 알려준 `cd..`를 zsh에 그대로 입력 시 오류. zsh에서는 `cd ..`처럼 공백이 필요함. 사용자는 원인을 몰라서 ChatGPT에 물어보고 해결함.

`dir`과 `ls`, PATH 설정, VS Code 줄 복사 단축키에서도 비슷하게 막힘. 수업 중에 같은 질문을 하는 사람도 많았음. 막힌 순간 바로 찾아볼 수 있는 곳이 있으면 좋겠다 싶어서 시작.

## 구상한 기능

- 검색: 명령어 또는 하고 싶은 일("상위 폴더 이동")로 찾기. 핵심 기능
- 사전: 카테고리별 탐색
- 학습 순서: 입문자 추천 순서
- 명령어 복사
- 오류 원인 표기: 실제 오류 메시지와 환경을 모르면 원인을 단정할 수 없어서 "오류 원인 추정"으로 표기
- 데이터 원칙: Ctrl→Command 같은 단순 치환 금지, 항목마다 확인 후 반영

## 중단 사유

1. 재방문 동기가 약함. 주요 대상이 각 OS를 처음 쓰는 사람인데, 익숙해지면 필요 없어지는 정보. 한 번 보고 나면 다시 올 이유가 크지 않다고 판단
2. 수요가 줄 가능성. AI가 명령어를 대신 써주는 경우가 늘어서, 직접 입력하는 일 자체가 줄 수 있다고 봄

## 배운 점

**검증 없이 기획 문서부터 늘림.** PRD와 세부 문서 6개를 썼지만 사용자 검증 단계는 진행하지 않음. 문서가 느는 것과 확인된 사실이 느는 것은 다름. 문제 자체는 수업에서 확인했지만, 이 서비스를 실제로 쓸지는 확인하지 못함. 다음엔 만들기 전에 이 부분부터 확인할 것.

**지속 사용만이 좋은 제품의 기준인지.** 중단하면서 가장 오래 한 고민. 재방문율이 낮으면 실패로 보기 쉽지만, 막힌 순간 한 번 해결해 주고 끝나는 제품도 가치가 있음. PRD 검증 문서에도 "재방문율이 낮아도 학습 완료 때문일 수 있다"고 적어 둠. 그렇다면 "다시 안 올 것 같다"는 이유로 중단한 게 맞는 판단이었는지는 확신 못 함.

**한 번 쓰는 제품은 평가 기준이 달라야 함.** 재방문율이 아니라 "한 번 왔을 때 막힌 문제를 풀었는지"로 재야 함. 다만 가치가 있는 것과 계속 운영할 이유가 있는 것은 별개.

**AI가 수요를 줄일지 늘릴지는 모름.** 직접 입력하는 일은 줄 수 있음. 반대로 AI가 써준 명령어가 왜 실패했는지 이해 못 하는 사람은 늘 수 있음. 열린 질문으로 남김.
